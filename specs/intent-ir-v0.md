# Intent IR v0

Status: implemented (`plan-ir.v0`)

## Purpose

Define the small, typed intermediate representation generated by a planner and consumed by deterministic software.

## Wire fields

- `schema_version`: exactly `plan-ir.v0`
- `request_id`: binds the plan to one input request
- `route`: `local`, `hybrid`, `external`, `clarify`, `defer`, or `deny`
- `steps`: ordered capability calls with stable identifiers
- `reason_codes`: stable machine-readable route reasons
- `confidence`: bounded candidate confidence in `[0, 1]`
- `clarification`: user-facing question for `clarify` routes

A step contains `step_id`, `capability_id`, typed `arguments`, an optional bounded `timeout_ms`, and an `idempotency_key`. An argument can reference only an earlier step using `{"$ref": "step_id"}`.

## Design constraint

The IR is data, not generated code. Unknown fields are rejected. Local routes require steps; clarify, defer, deny, and external routes cannot smuggle local steps. Write and physical steps require idempotency, and no step executes until the complete plan passes deterministic validation.
